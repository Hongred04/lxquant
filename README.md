# lxquant · 大金融中长线

一个只做一件事的工具：**在大盘跌到位时，买 1 家银行 + 1 家保险，拿 40 天。**

打开就是一块屏：

```
┌ 进场信号 ──────────┬ 净值曲线（10 年，可悬停）──────┐
│ -2.89%  ● 可以买    │ 年化 3.8%  回撤 -10.2%  夏普 .61 │
│ 120 日偏离度轨道     ├ 每年赚多少（柱状图）─────────┤
├ 今天买这两只 ──────┤ 历史机会（39 次，逐次明细）───┤
│ 浙商银行 / 新华保险  │                                 │
├ 我的持仓（第 N/40 天）┤                                 │
└────────────────────┴─────────────────────────────────┘
```

## 规则

| | |
|---|---|
| 进场 | 上证指数相对 20 日均线跌幅 > 2% |
| 选股 | 银行里避差分最高的 1 只 + 保险里最高的 1 只 |
| 持有 | 40 个交易日，到期全卖，中途不看 |
| 仓位 | 各一半 |

参数写死在 `lxquant/finance.py`，界面不给调 —— 给的旋钮越多，越容易用调出来的参数骗自己。

## 成绩（2016-01 ~ 2026-11，10.8 年，前复权）

| 年化 | 最大回撤 | 夏普 | 卡玛 | 调仓 |
|---|---|---|---|---|
| **+3.8%** | **−10.2%** | **0.61** | **0.37** | 10 次 |

分年度：2016 +1% / 2017 +6% / 2018 −3% / 2019 **+17%** / 2020 −1% /
2021 −1% / 2022 −1% / 2023 +1% / 2024 **+18%** / 2025 +4% / 2026 +2%

**11 年 8 正 3 负，最差一年 −3%。** 收益全靠 2019、2024 两个券商年，
其余年份接近零 —— 这不是每年都赚的东西，一年大概只动手一两次。

另有一份「历史机会」口径（每次破位都算一次，不重叠）：
**39 次机会、38 次已到期、23 胜 15 负、平均 +1.65%/次**，同期上证 +0.51%。

> 两个口径不能互相替代：净值曲线是「每 40 天固定调仓」，
> 机会清单是「每次破位都买」。前者回答年化多少，后者回答每次实际发生了什么。

## 跑起来

```
双击 启动选股.bat
```

浏览器打开 `http://127.0.0.1:8777`。首次启动会拉 81 只大金融的日线（约 2 秒）。

## 已知偏差（都写在明处）

1. **回测池子只含当前还在交易的票。** 2016 年后退市的拿不到，而退市股通常暴跌 ——
   所以 +3.8% 是**高估**的。
2. **样本只有 10.8 年、10 次调仓。** 统计上非常薄，真实水平可能是 1% 也可能是 6%。
3. **前复权是事后视角。** 分红送转按今天的复权因子回算，实盘会有现金分红和除权跳空。
4. **到期日按工作日推算，不含法定节假日。** 真实到期可能顺延一两天。

## 目录

| 路径 | 是什么 |
| --- | --- |
| `run.py` | 启动入口（HTTP 服务） |
| `lxquant/finance.py` | **唯一在用的策略**：择时 + 选股 + 落盘 |
| `lxquant/fin_pos.py` | 持仓跟踪：买了没 / 第几天 / 还剩几天 / 浮盈亏 |
| `web/` | 前端：纯 HTML/CSS/JS，无框架、无依赖；**改了要构建**，见下 |
| `data/` | 配置与运行数据（行情缓存 `data/cache/` 不进库，会自动重下） |
| `runtime/` | 自带的 Python 运行时，不进库 |
| `tools/` | `build.js` 压缩前端；`check.py` 一键自检 |
| `tests/` | 纯标准库单测，`runtime/python.exe -m tests.run` |
| `AGENTS.md` | 给 AI / 接手的开发约定和已知的坑 |

## 接口

| 路径 | 说明 |
|---|---|
| `GET /api/fin` | 当前信号、两只票（含因子明细）、市场状态 |
| `GET /api/fin/history` | 10 年净值曲线 + 分年度 + 指标（离线算好存盘） |
| `GET /api/fin/trades` | 39 次历史机会明细（离线算好存盘） |
| `GET/POST /api/fin/pos` | 持仓：`{action:"open"|"close"}` |
| `POST /api/fin/refresh` | 强制重算（刷新按钮走这个） |

`history` 和 `trades` 都是离线脚本生成的，不在请求里跑 —— 算一次要读 1 GB 长表：

```
runtime/python.exe ../factor_lab/71_dump_history.py    # 净值曲线
runtime/python.exe ../factor_lab/70_dump_trades.py     # 机会清单
```

## 不进的目录

`data/cache/`（500MB+ 行情缓存，删了自动重下）、`data/export/`、`runtime/`、
`data/long_all.pkl`（1 GB 长表）、`data/fin_state.json`（运行缓存）。

## 改完代码怎么验证

```
./runtime/python.exe tools/check.py
```

语法、单测、前端语法、构建新鲜度一次查完。

**改了 `web/app.js` 或 `web/style.css` 必须重建**：

```
node tools/build.js
```

原因：服务端 `_static()` 看到同名 `.min` 就**优先发压缩版**。只改源文件不重建，
刷新看到的是旧代码 —— 这个坑很容易误判成「改了没用」。调试用 `?raw=1` 看源码版。
